## Content guidance for proof-oriented sections

When adding or updating `Results`, `Testimonials`, or `Projects` components, do not use unsupported or invented statistics. Avoid made-up claims such as client counts, revenue generated, conversion lifts, traffic numbers, or other metrics that are not backed by real evidence.

Until verified evidence exists, use methodology-based proof instead:

- clear process steps that explain how the work is planned, built, reviewed, and shipped
- project screenshots that show real interface work
- before/after explanations that describe concrete changes without inventing numbers
- real shipped work with transparent context about what was delivered
- case-study notes that distinguish confirmed outcomes from goals, assumptions, or next steps

If a future section needs performance claims, include only metrics that can be traced to a reliable source and document that source near the component or case-study content.
